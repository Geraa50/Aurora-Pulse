# Aurora-Pulse — план разработки

**Игра:** Triple Mahjong (Match-3 по тройкам одинаковых плиток)  
**Движок:** Godot 4.x + GDScript  
**Цель:** Devfest Hackathon → порт на **Aurora OS** (touch-only)  
**Репозиторий:** [Geraa50/Aurora-Pulse](https://github.com/Geraa50/Aurora-Pulse)

---

## 1. Соответствие ТЗ хакатона

| Требование | Как закрываем | Критерий готовности |
|------------|---------------|---------------------|
| ≥ 1 завершённый уровень | Уровень `level_01` с победой/поражением и кнопкой «ещё раз» | Можно пройти от старта до экрана победы без багов |
| Только касания | `TouchInput`, кнопки `Button`/`TextureButton`, жесты через UI | В релизной сборке нет обязательных hotkey |
| Прогресс | Счётчик оставшихся плиток или звёзды | HUD виден во время игры |
| Оригинальные / открытые ассеты | `docs/ASSETS.md` + лицензии в `game/assets/` | Все файлы с указанным источником |

## 2. Игровой дизайн (MVP)

### 2.1. Правила Triple Mahjong

1. Поле: набор плиток с **слоями** (верхние перекрывают нижние).
2. Плитка **доступна**, если её не перекрывает ни одна плитка верхнего слоя; самый верхний слой всегда доступен.
3. Игрок выбирает до **3 доступных** плиток одного типа → они исчезают, прогресс обновляется.
4. **Победа:** плиток не осталось. **Поражение (опционально в MVP):** нет возможных троек — показать «нет ходов» + рестарт.
5. Первый уровень: фиксированная раскладка (12–24 плитки, 4–6 типов), без генератора.

### 2.2. Вне MVP (после хакатона)

- Подсказка, перемешивание, таймер
- Карта уровней, мета-прогресс
- Звук, анимации слоёв
- Генератор уровней

## 3. Архитектура (Godot)

```
game/
├── project.godot
├── scenes/
│   ├── main_menu.tscn
│   ├── game.tscn          # корень уровня
│   ├── board.tscn         # сетка/слои плиток
│   ├── tile.tscn          # одна плитка
│   └── ui/
│       └── hud.tscn       # уровень, прогресс, пауза
├── scripts/
│   ├── autoload/
│   │   └── game_state.gd  # уровень, сцены
│   ├── board/
│   │   ├── board.gd       # раскладка, доступность
│   │   └── tile.gd        # выбор, подсветка
│   ├── rules/
│   │   └── match_rules.gd # «свободна ли», валидная тройка
│   └── levels/
│       └── level_01.gd    # данные раскладки (Resource или JSON)
└── assets/
    ├── tiles/             # спрайты плиток (CC0 / свои)
    └── fonts/
```

**Принципы**

- Логика правил — в `match_rules.gd` (тестируемо без сцены).
- Ввод — только сигналы UI (`pressed`, `gui_input`), не `_unhandled_key_input` в релизе.
- `GameState` autoload — смена сцен и текущий уровень.

## 4. Фазы и сроки (ориентир ~2–3 недели)

### Фаза 0 — Окружение (0.5–1 день) ✅ частично

- [x] Git: [Aurora-Pulse](https://github.com/Geraa50/Aurora-Pulse)
- [x] Инструменты агента: ast-index, caveman, DAE (см. `docs/TOOLS_SETUP.md`)
- [ ] Godot 4.3+ установлен, проект открывается из `game/`
- [ ] GUT или встроенные тесты для `match_rules.gd`

### Фаза 1 — Ядро механики (3–4 дня)

| Задача | Результат |
|--------|-----------|
| Сцена `tile` + типы (id, слой, позиция) | Кликабельная плитка |
| `match_rules`: свободна / тройка | Unit-тесты зелёные |
| `board`: раскладка из `level_01` data | Плитки на экране |
| Выбор 3 одинаковых → удаление | Прогресс + сигнал `tiles_cleared` |

**Definition of done:** в редакторе можно вручную пройти уровень до пустого поля.

### Фаза 2 — Один завершённый уровень (2–3 дня)

| Задача | Результат |
|--------|-----------|
| Экран победы + «Играть снова» | Замкнутый цикл |
| HUD: уровень + прогресс | ТЗ обратной связи |
| Главное меню → уровень 1 | Минимальный flow |
| Полировка touch (размер hitbox ≥ 48dp) | Удобно на телефоне |

### Фаза 3 — Контент и ассеты (2 дня)

| Задача | Результат |
|--------|-----------|
| 4–6 наборов плиток (SVG/PNG) | Свои или Kenney/CC0 |
| `docs/ASSETS.md` | Лицензии |
| Звук (опционально) | 1–2 SFX с лицензией |
| Баланс `level_01` | Проходимо за 3–8 мин |

### Фаза 4 — Подготовка к Aurora OS (3–5 дней, после MVP)

| Задача | Результат |
|--------|-----------|
| Исследовать Godot export / обёртку для Sailfish/Aurora | Выбран путь (RPM, QML shell, или отдельный UI) |
| Отключить keyboard shortcuts в export | Только touch |
| Разрешения, иконка, `.desktop` / Harbor требования | Чеклист Aurora |
| Тест на эмуляторе / устройстве Aurora | Сборка устанавливается |

> Точные шаги порта зависят от версии Aurora SDK и поддержки Godot; заложить **1 неделю буфера** после хакатона.

### Фаза 5 — Сдача хакатона (1 день)

- [ ] Запись геймплея (30–60 с)
- [ ] README: как собрать, скриншоты
- [ ] Проверка ТЗ чеклистом (см. §1)
- [ ] Push в `main`

## 5. Тестирование

| Уровень | Что | Инструмент |
|---------|-----|------------|
| Unit | `is_tile_free`, `can_match`, обновление прогресса | GUT / `@tool` tests |
| Интеграция | Загрузка `level_01`, полная победа | Headless или manual QA |
| Touch | Тап по краям плиток, отмена выбора | Устройство / Godot remote |
| Регресс | После порта — те же тесты правил | CI (опционально) |

**DAE (опционально):** для фич `001-core-triple-match`, `002-level-01` — Gherkin в `features/` + сценарии «Given board with … When player selects 3 matching … Then …».

## 6. Риски и митигация

| Риск | Митигация |
|------|-----------|
| Сложность «свободной» плитки | Начать с 1 слоя, потом 2 слоя |
| Godot на Aurora нестабилен | Ранний spike в фазе 4; запасной UI на QML только для меню |
| Мало времени | Жёсткий MVP: 1 уровень, без звука/анимаций |
| Ассеты | Kenney, OpenGameArt CC0; не тянуть commercial art |
